DÉPANNER AVEC CLAUDE — Claude Code sur la clé VANGUARD
======================================================
English: README.txt

Claude Code, l'assistant d'Anthropic, aide à trouver la cause d'une panne sur l'ordinateur d'un proche
(lenteur, plantage, virus, réseau, démarrage). Il lit l'ordinateur, explique, et propose ; il demande avant
toute commande qui change quelque chose. Certaines commandes de simple lecture passent sans demander, et ce
qu'elles montrent part aussi chez Anthropic. Il se sert de Vanguard, sur la même clé, pour le diagnostic.

Il faut : un compte Claude (abonnement Pro ou Max, ou console Anthropic), Internet, et l'accord du
propriétaire de l'ordinateur : ce que Claude lit (journaux, réglages, noms de fichiers) part chez Anthropic.


1. LANCER

   Windows (10 version 1809 ou plus récent) : double-cliquer « Depanner avec Claude.bat » à la racine de la clé.
   Linux : dans un terminal,   bash /run/media/$USER/VANGUARD/Claude/depanner.sh
           (ou /media/$USER/VANGUARD/… sur Ubuntu, Debian, Mint).
   Ordinateur qui ne démarre plus : démarrer sur SystemRescue (menu de la clé), puis la même commande que sous
   Linux. Claude y monte le disque en lecture seule pour diagnostiquer.

   La première fois, Claude donne une adresse de connexion (le navigateur de cet ordinateur ne s'ouvre pas) :
   l'ouvrir sur VOTRE téléphone, jamais dans le navigateur de cet ordinateur (il garderait votre compte
   connecté après votre départ), se connecter, et recopier le code s'il en demande un.


2. FINIR

   Taper /exit dans Claude. Le lanceur déconnecte le compte et efface de l'ordinateur Claude Code, la
   connexion, la conversation et les journaux de Claude Code de cette session. « Déconnecté » n'est affiché
   que si Anthropic a confirmé la fin de la connexion. S'il affiche « Déconnexion NON confirmée » (hors
   ligne, ou une version de Claude Code qui ne le dit pas), terminer la session sur claude.ai (Réglages ›
   Compte).
   Fenêtre fermée par sa croix : sous Windows, un gardien efface quand même ;
   au moindre doute (ou sous Linux), relancer le lanceur une fois, puis /exit : il efface d'abord ce qui
   était resté.
   Après un ordinateur douteux (virus possible), ou s'il s'est éteint ou a planté en pleine session :
   terminer aussi la session sur claude.ai (Réglages › Compte), pour que la connexion ne vaille plus rien
   ailleurs.
   Connecté par erreur dans le navigateur de cet ordinateur : s'y déconnecter de claude.ai avant de partir.


3. CE QUI EST PROTÉGÉ

   - Rien n'est installé : le programme est copié dans un dossier temporaire, lancé de là, puis effacé.
   - La connexion à votre compte Claude n'est jamais écrite sur la clé ; elle vit seulement dans le dossier
     temporaire de la session (à votre seul compte ; sous Windows, refusé sur un disque sans droits Windows,
     FAT ou réseau), effacé à la fin.
   - Avant le lancement, le programme est vérifié : sous Windows, sa signature numérique, contrôlée par
     Windows, faite par « Anthropic, PBC » (nom, pays et numéro d'entreprise du certificat), et son empreinte ;
     sous Linux, la signature d'Anthropic sur la liste des empreintes, et l'empreinte du programme.
   - Les connecteurs de votre compte Claude (courriel, fichiers en ligne, agenda) ne sont pas chargés, ni
     aucun serveur MCP. Le navigateur de cet ordinateur ne s'ouvre jamais.
   - Des consignes posées sur l'ordinateur pour Claude, dans un dossier au-dessus du dossier temporaire
     (CLAUDE.md, CLAUDE.local.md, AGENTS.md, .mcp.json, un dossier .claude), ou des réglages imposés à Claude
     Code par l'ordinateur (/etc/claude-code, C:\Program Files\ClaudeCode, stratégies du registre) : le
     lanceur refuse de démarrer, et dit pourquoi. Seule exception : le dossier .claude du dossier personnel
     (Claude Code déjà utilisé sur cet ordinateur), où seules des consignes (CLAUDE.md, AGENTS.md, rules) font
     refuser.
   - Claude reçoit des consignes de dépannage (CLAUDE.md, dans ce dossier) : diagnostiquer en lecture seule,
     expliquer la cause avant de corriger, ne rien changer sans accord, ne jamais couper l'antivirus, le
     pare-feu ni les mises à jour, respecter la vie privée du proche.
   - Pas de mise à jour automatique : la version vérifiée est celle qui tourne. Vanguard met la clé à jour
     sur l'ordinateur de son propriétaire.

   Ce que vous acceptez quand même : Claude peut se tromper. Lisez chaque commande avant de dire oui.


4. LIMITES

   - Windows et Linux 64 bits (x86-64). Sous Windows ARM, la version x86-64 tourne en émulation.
   - Le lanceur Windows est essayé sous PowerShell sous Linux, les appels propres à Windows (droits,
     signature, disque, gardien) remplacés par des doublures : il n'a pas encore tourné sur un vrai Windows.
   - Sous Linux sans gpg, la signature d'Anthropic ne peut pas être vérifiée : le lanceur le dit et demande.
   - Sous Windows, la liste des empreintes n'est pas vérifiée par une signature (pas de gpg) : seule la
     signature d'Anthropic sur le programme l'est.
   - Sous Windows, les variables de certificats de l'ordinateur sont retirées, mais Claude Code se fie, comme
     le navigateur, aux certificats installés dans Windows : un ordinateur qui inspecte les connexions
     (antivirus, entreprise, ou virus qui y a ajouté le sien) peut les lire.
   - Sous Windows, tout compte peut créer un dossier C:\.claude : le lanceur refuse s'il existe au départ,
     pas s'il apparaît pendant la session.
   - Le lanceur vit sur la même clé que le programme : il voit une copie abîmée, pas une clé réécrite en
     entier. Une clé qui a quitté vos mains repasse par Vanguard (sur votre ordinateur) avant de servir.
   - Un virus qui tourne déjà sous le même compte peut lire la connexion pendant la session : rien ne l'en
     empêche. Sur un ordinateur qu'on croit infecté, démarrer plutôt sur SystemRescue (menu de la clé), et
     terminer la session sur claude.ai après.
   - Sous Windows, Claude Code peut demander Git for Windows pour certaines commandes : l'installer seulement
     avec l'accord du propriétaire, depuis git-scm.com ou winget.
